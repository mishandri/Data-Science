# Рекомендательная система для интернет-магазина

## Описание проекта

Данный проект представляет собой решение задачи ранжирования (Learning to Rank) для интернет-магазина. Система предсказывает релевантность товаров для каждого пользователя, что позволяет формировать персонализированные рекомендации и повышать ключевые бизнес-метрики (CTR, конверсию, удержание пользователей).

### Бизнес-ценность
- **Повышение CTR** за счет показа релевантных товаров в топе выдачи
- **Увеличение конверсии** благодаря точному соответствию товаров интересам пользователей
- **Снижение оттока** через улучшение пользовательского опыта
- **Автоматизация** процесса формирования рекомендаций

## Структура данных

### Исходные файлы
| Файл | Описание | Количество записей |
|------|----------|-------------------|
| `items.csv` | Информация о товарах (категория, сложность, популярность) | 120 |
| `users.csv` | Информация о пользователях (возраст, уровень дохода) | 900 |
| `train_interactions.csv` | Обучающие данные взаимодействий с relevance | 30,000+ |
| `test_interactions.csv` | Тестовые данные для предсказания (без relevance) | 3,993 |

### Особенности данных
- **Категориальные признаки**: `category` (товары), `income_level` (пользователи)
- **Числовые признаки**: `age`, `complexity`, `popularity`
- **Целевая переменная**: `relevance` (1-5) - релевантность товара для пользователя

## EDA (Exploratory Data Analysis)

### Анализ целевой переменной
- Распределение `relevance` показывает преобладание значений 3-4
- Среднее значение: ~3.5
- Стандартное отклонение: ~0.9

### Анализ признаков
- **Категории товаров**: равномерное распределение (electronics, clothing, books, furniture)
- **Уровень дохода**: преимущественно "medium" (~70%)
- **Возраст пользователей**: равномерное распределение в диапазоне 18-69 лет

### Корреляции
- `popularity` слабо коррелирует с `complexity` (r ≈ 0.15)
- `relevance` имеет наибольшую корреляцию с `category` и `income_level`

## Архитектура решения

### 1. Предобработка данных
- Объединение взаимодействий с данными пользователей и товаров
- Кодирование категориальных признаков (Label Encoding)
- Масштабирование числовых признаков (StandardScaler)
- Формирование групп по `user_id` для ранжирования

### 2. Модель
**Выбор модели**: XGBoost LambdaMART
- **Objective**: `rank:ndcg` - оптимизация NDCG@5
- **Преимущества**:
  - Специализирован для задач ранжирования
  - Учитывает порядок элементов внутри группы
  - Оптимизирует непосредственно целевую метрику
  - Масштабируется на большие данные

### 3. Архитектура обучения

**Этап 1: Подготовка данных**
- Загрузка и объединение данных из файлов `items.csv`, `users.csv`, `train_interactions.csv`
- Кодирование категориальных признаков (`category`, `income_level`)
- Масштабирование числовых признаков (`age`, `complexity`, `popularity`)
- Формирование групп по `user_id` для ранжирования

**Этап 2: Разделение на обучающую и валидационную выборки**
- Обучающая выборка: 80% пользователей
- Валидационная выборка: 20% пользователей
- Важно: разделение происходит по пользователям, а не по строкам

**Этап 3: Обучение модели XGBoost LambdaMART**
- Objective: `rank:ndcg`
- Метрика: `ndcg@5`
- Параметры: `max_depth=6, learning_rate=0.1, subsample=0.8`
- Ранняя остановка: 20 раундов без улучшения

**Этап 4: Валидация модели**
- Расчет NDCG@5 на валидационной выборке
- Проверка достижения целевого порога ≥ 0.9
- Анализ важности признаков

**Этап 5: Предсказание на тестовых данных**
- Применение обученной модели к test_interactions.csv
- Постобработка предсказаний (нормализация в диапазон 1-5)
- Сохранение результатов в submission.csv
